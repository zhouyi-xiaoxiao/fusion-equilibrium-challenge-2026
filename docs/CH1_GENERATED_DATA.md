# DIII-D training prerequisites (generated data)

`ch1/train.sh` retrains all 38 weight files from **generated data**: feature caches computed from the public `diii_d_train`
parquet files, PCA bases, the metric matrices of the metric loss, the out-of-fold teacher statistics and the frozen blend
constants. Their generation is CPU work (declared, not capped by the rules) except two small GPU items listed in PROVENANCE.md
section 4. The rules allow generated data to be shipped with its sha256 when the code, configuration and seeds are included:

- `weights/GENERATED.sha256` lists every generated file the training run reads (`<bytes> <sha256> <path under the work
  directory>`). The list was produced by running `ch1/train.sh` in a clean room with the read audit on
  (`tools/open_audit/sitecustomize.py`, `FEC_OPEN_AUDIT=<dir>`): every file opened by the training processes, minus code, the
  environment, the 49 files of `weights/MANIFEST.sha256` and the run's own outputs.
- Measured set: 41 files, 18.26 GB — the canonical v2.2 cache `stage11_ch1/e_cx/h150/feat/{train,holdout,test}` (23 files,
  12.47 GB), the canonical v2.1 cache `stage11_ch1/f_corr_canon/feat_all/{train,holdout,test}` (11 files, 5.78 GB) and 7 small
  metric files (8.7 MB). The `test` files are input features of the public-test shots (no labels exist for them): the trainers
  write predictions for them at the end of training; no fitted quantity uses them.
- Completeness check: a clean-room training whose work directory held only these 41 files (verified copies) and the 49 files of
  `weights/MANIFEST.sha256` reproduced the 38 weight files (34 sha256-identical, 4 tensor-identical; 1.75 GH200 GPU-hours).
- `MANIFESTS=weights/GENERATED.sha256 bash tools/fetch_weights.sh <hf|url|dir> <source>` places and verifies them.
- Profile `hc10x24`: its 24 heads train on one further cache, the canonical v2.2 rows of all 7,041 labelled shots
  (`stage11_ch1/l_corr/feat22_all`). It is not shipped: `ch1/build_feat22.py` (called by `ch1/train.sh`) builds it from files of
  the list above — rows of `e_cx/h150/feat/train` followed by `e_cx/h150/feat/holdout`, with offsets, times and labels checked
  against `f_corr_canon/feat_all/train` — and verifies the sha256 of the result against the development cache
  (`FEAT22_X_SHA256` in `ch1/profiles/hc10x24.sh`; 4.92 GB; clean room: identical).
- Profile `xhc`: its training stage FT (`ch1/train_xhc_ft.sh`) reads, besides the files above, the two row-order file lists of the
  canonical v2.2 cache (`stage11_ch1/e_cx/h150/feat/{train,holdout}/files.txt`, `weights/GENERATED_XHC.sha256`) and the public
  `diii_d_train` parquet files (labels of the training shots). From the labels it builds, on the CPU, the reference-contour cache
  (`ch1d_liloss/li_prep.py`) and the label-polygon bank (`j_dlcfs_contour/jc_bank_label.py`); from the base members' own coefficients
  on the training rows (`jc_c0.py`, one GPU forward pass) the anchor bank with the per-shot loss weights and the 256 held-out gate rows
  (`jc_bank.py`). These are regenerated by every run of the stage and are not shipped.
- The scripts below produced them; they are shipped under `src/` as they were run (paths parametrised through `WS` / `SCR`).
  They are not needed to train from the shipped generated data.

| generated data (work-directory path) | content | produced by | cost |

| `stage11_ch1/e_fold2_offset/h150_cfl/feat` | mirror-canonical v2.1 cache and scaler — heads | `stage11_run/e_fold2_offset/e_canon.py` (VARIANT=cfl) | minutes |
| `stage11_ch1/f_corr_canon/feat_all` | the v2.1 canonical cache of all 7,041 labelled shots (train + holdout merged) — head training | `stage11_run/f_corr_canon/f_merge.py` (`f_prep.sh`) | minutes |

| `stage11_ch1/f_corr_canon/full/corrector/blend_frozen_gv21c.json` | 33 frozen constants of the robust fusion of heads and map (fitted on a 344-shot validation slice of the 6,891-shot development run) | `stage11_run/f_corr_canon/f_heads.sh` (dev-style heads) + `ch1_corrector/cc_blend.py` | about 0.4 GPU-h (estimate) |

Seeds: every trainer takes explicit seeds (`ch1/train.sh` and the scripts above); the frozen blend constants and the
teacher statistics are deterministic functions of the seeded models. The 150-shot development holdout is
`splits/d3d_holdout150.txt` (= sorted labelled file names 1000–1150 of the 1,150-shot subset `splits/d3d_subset1150.txt`).
